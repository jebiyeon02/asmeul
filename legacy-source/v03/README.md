# Hollow · macOS soundscapes 0.3

Mac에서 재생되는 소리에 잔향, 부드러운 톤, 좌우 오빗을 적용하는 네이티브 앱입니다. **제품 출시판이 아니라 첫 기술 검증용 구현**입니다.


## 0.3 — 비 오는 사무실과 황혼의 호숫가

사용자가 제시한 두 영상의 소리 목록을 기준으로 **Tokyo Office / Twilight Lake**를 추가했습니다. 상단 두 장면 카드에서 선택합니다. 자세한 구성과 원본과의 차이는 [REFERENCE_NOTES.md](REFERENCE_NOTES.md)에 적었습니다.

- **Tokyo Office**: 비·먼 도시·필기·키보드·배경의 일본어 방송. 필기·키보드에는 작업/휴식 구간이 있습니다.
- **Twilight Lake**: 잔물결·풀벌레·풀·바람에 드물게 들리는 방울/나무 소리와 별도 피아노 레이어.
- **심야 라디오와 사무실의 자체 음악을 제거했습니다.** 재즈 파일은 앱에 포함하지 않으며, 두 경로에서 음악 뱅크를 읽지 않는 테스트를 추가했습니다.
- 일본어 방송은 실제 뉴스가 아닌 기기 내 합성 음성의 가상 일상/문화 방송입니다. 일본어 방송 슬라이더로 조절합니다.
- 사무실의 필기·키보드, 호수의 방울·나무 소리, 호수의 피아노를 각각 조절할 수 있습니다.
- 피아노 0%에서는 호숫가 자연 소리와 작은 효과만 재생됩니다. 사용자가 다른 앱에서 재생한 음악은 별도의 음악 슬라이더로 믹스할 수 있습니다.
- 새 두 장면과 라디오 프리셋은 기본적으로 배경만 듣기 상태로 선택됩니다.

### 0.3 검증

- release build, 10 프리셋 × 3 sample rates DSP 테스트, 5 배경 장면 × 3 sample rates 테스트 통과 (UBSan).
- 라디오/사무실에서 피아노 뱅크 유무와 피아노 음량을 바꿔도 출력이 동일함을 검증.
- 새 앱의 상단 장면 카드, 음악 없음 안내, 일본어 방송 조절과 실시간 버퍼/출력 피크를 UI에서 확인. 임시 빌드 위치에서 코드 서명 검증 후 앱과 ZIP 생성.
- 11개 오디오 소재 decode 및 가상 일본어 방송 4개 생성 성공.
- 새 실제 엔진 40초 렌더링: Tokyo Office RMS 0.0306 / peak 0.1822, Twilight Lake RMS 0.0134 / peak 0.3014, 음악 없는 Tokyo Radio RMS 0.0127 / peak 0.0774. 전 구간 유한값과 피크 상한 확인.
- `previews/tokyo-office.wav`, `previews/twilight-lake.wav`, `previews/tokyo-radio.wav`는 이 버전의 배경만 렌더링한 예시입니다. 시스템 오디오 녹음이 아닙니다.

## 이전 0.2 변경 기록 — 당시 구현 (현재 동작은 위의 0.3 참고)

이번 업데이트는 음악과 **별도의 환경음 레이어**를 믹스합니다. 세 장면은 실제 재생 가능한 소리를 포함합니다.

- **동굴**: 실제 동굴 입구의 스테레오 물방울 + 깊은 메아리 레이어.
- **창가의 비**: 실내 열린 창가에서 녹음한 실제 스테레오 강우.
- **Tokyo Radio / 심야 라디오**: 오리지널 느린 재즈풍 연주 + 일본어 DJ 멘트 4개 + 라디오 대역/포화 질감 + 오른쪽에 놓인 작은 스피커 + 창밖의 비. DJ가 말할 때 재즈 볼륨이 자동으로 줄어듭니다.

Cave / Rainy Room / Tokyo Radio 프리셋을 선택하면 해당 배경이 같이 선택됩니다. 다른 음악 공간 프리셋에도 BE THERE 패널에서 배경을 독립적으로 붙일 수 있습니다. 나머지 공간 프리셋에는 아직 전용 환경음이 없습니다.

**음악 / 배경 소리 / 거리감**을 각각 조절할 수 있고, **배경만 듣기**를 켜면 입력 음악을 믹스에서 제외합니다. Tokyo Radio는 기본적으로 배경만 듣기로 시작해 원곡과 재즈가 겹치지 않게 했습니다. 라디오의 DJ 말소리 슬라이더를 0으로 두면 말소리 없이 들을 수 있습니다.

- 환경음은 녹음 길이를 유지하며 2.4초 루프 크로스페이드를 적용합니다. 이는 무한 생성이 아니라 반복 재생입니다.
- 장면 전환은 약 0.55초 시간 상수의 페이드로 이전 공간과 새 공간을 섞습니다.
- 원음 비교는 환경음·재즈·DJ도 함께 제외합니다. 음악 믹서를 0으로 설정했더라도 A/B는 입력 원음을 들려줍니다.
- 수면 타이머는 환경음도 함께 줄입니다. 끝나면 탭이 해제되므로 외부 음악 앱의 원래 재생은 계속됩니다.
- DJ는 실제 방송이 아닌 **직접 쓴 일본어 대본 + macOS 합성 음성**입니다. 합성된 멘트는 앱 실행 시 메모리에서 준비되며 준비 실패 시 UI에 표시됩니다. 기기에 설치된 음성 품질에 따라 청감이 달라집니다.
- 실제 녹음 원본·라이선스·가공 방식은 [SOUND_CREDITS.md](SOUND_CREDITS.md)에 기록했습니다. 현 버전은 HQ MP3 소재를 사용하며 무손실 마스터라고 표시하지 않습니다.

`previews/`의 40초 WAV 3개는 시스템 오디오를 캡처하지 않고 배경 레이어만 렌더링한 예시입니다. `./scripts/previews.sh`로 현재 엔진과 설치된 일본어 음성으로 다시 생성할 수 있습니다.

### 0.2 검증

- 8개 음악 프리셋 및 3개 배경 장면으로 확장, release build 성공.
- 기존 DSP 테스트와 별도 soundscape 테스트: 44.1/48/96kHz에서 무음 입력의 배경 재생, 반복 경계, 장면 전환, A/B, 타이머 페이드, 잘못된 소재 거부 통과 (UBSan).
- 실제 번들 녹음 3개 및 오리지널 재즈 파일 decode 성공, 일본어 멘트 4개 PCM 생성 확인.
- 실제 엔진의 40초 스테레오 렌더링: cave RMS 0.0190 / peak 0.3970, rain RMS 0.0435 / peak 0.2935, radio RMS 0.0625 / peak 0.4208. 렌더링 전 구간 유한값·피크 상한 검사 통과.
- 새 네이티브 UI에서 환경음 믹서, DJ 준비 완료, 48kHz 실시간 버퍼 증가와 0이 아닌 출력 피크를 확인했습니다.
- 숫자 검증은 청감 평가를 대체하지 않습니다. 헤드폰별 현장감, 루프 반복감, DJ의 자연스러움은 추가 청취 튜닝 대상입니다.

## 실행

1. `build/Hollow.app`을 엽니다. macOS 14.4 이상이 필요합니다. 현재 실행 파일은 Apple Silicon용입니다.
2. 음악을 재생하고 **효과 시작**을 누릅니다. 처음에는 macOS가 요청하는 시스템 오디오 접근을 허용해야 합니다.
3. 공간 카드를 선택하고 Space / Warmth / Orbit을 조절합니다.
4. **A/B 원음 비교**로 효과를 비교합니다. A/B에서도 Hollow의 출력 볼륨과 피크 상한은 유지됩니다.
5. **효과 끄기** 또는 ⌥⌘H로 탭을 해제하면 원래 앱의 소리가 그대로 돌아옵니다.

창을 닫아도 메뉴바에서 계속 동작합니다. 완전히 종료하려면 메뉴바 패널의 종료 버튼 또는 ⌘Q를 사용하세요.

하단의 미터, 샘플레이트, 누적 버퍼 수로 동작을 확인할 수 있습니다. 버퍼는 늘어나는데 미터가 계속 0이면 재생 상태, 선택 소스, macOS 권한을 확인하세요. 무음과 권한 차단에 따른 0 샘플은 현재 자동 구별하지 않습니다.

## 구현된 기능

- Core Audio Process Tap → private aggregate device → C++ DSP → 기본 출력 장치
- 시스템 전체 또는 Core Audio 프로세스 한 개 선택, Hollow 자체 출력 제외
- `mutedWhenTapped`를 이용한 원음 중복 재생 방지
- Cathedral / Cave / Concert Hall / Underwater / Rainy Room / Space / Bedroom / Tokyo Radio 프리셋
- 자체 알고리즘 리버브, 로우패스 기반 Warmth, 좌우 음량 이동 Orbit
- 20ms 파라미터 보간, A/B, 출력 볼륨, ±0.95 피크 안전 상한
- 메인 창과 메뉴바 패널, 전역 ⌥⌘H 단축키
- 앱 bundle ID별 마지막 설정 기억, JSON 프리셋 가져오기/내보내기
- 15/30/60분 효과 종료 타이머. 마지막 15초 동안 효과가 줄어듭니다. **음악 자체를 멈추지는 않습니다.**
- 종료/시작 실패 시 탭·집계 장치 정리
- 잠자기, 출력 장치/샘플레이트 변경, 콜백 중단 시 정지와 원음 복구

## 기획서와 현재 구현의 차이

| 기획 항목 | 현재 상태 |
|---|---|
| 실측 IR 컨볼루션 | 미구현. 외부 IR을 쓰지 않는 8개 지연선 기반 알고리즘 잔향 |
| HRTF / 8D 공간 렌더링 | 미구현. Orbit은 좌우 스테레오 이동이며 3D/HRTF가 아님 |
| Slow / 피치 다운 | 미구현. UI에는 실제 로우패스 기능인 Warmth만 표시 |
| 5밴드 EQ / 컴프레서 / 브릭월 리미터 | 미구현. 마지막 안전 클램프만 존재하며 큰 신호에는 왜곡 가능 |
| 앱 다중 선택 / 브라우저 자식 프로세스 묶음 | 미구현. 프로세스 하나 선택 또는 전체 시스템. 브라우저는 전체 시스템으로 먼저 시험 |
| Rainy Room 배경 빗소리 | 0.2에서 실제 녹음 레이어 구현 |
| 출력 자동 재연결 | 장치 변경 시 정지. 새 장치에서 사용자가 다시 시작 |
| Video Sync / 20ms 지연 / CPU 6% | 보장하지 않음. 종단 간 지연과 CPU 목표는 별도 계측 필요 |
| Apple Music / DRM 호환성 | 미검증. 모든 스트리밍 서비스 캡처를 보장하지 않음 |
| App Store / sandbox / notarization | 미검증. 현재 로컬 ad-hoc 서명, sandbox 미적용 |
| 헤드트래킹 / AU 호스팅 / 결제 | 후속 개발 |

스테레오 Float32 PCM 경로를 대상으로 합니다. 멀티채널 장치는 첫 두 출력 채널만 사용하므로 현재 지원 범위에서 제외합니다. AirPods, 외장 DAC, 앱 재시작 시 프로세스 재선택과 장시간 안정성은 추가 실기기 검증이 필요합니다. 프로세스 목록은 오디오를 사용하는 시스템 프로세스도 포함할 수 있습니다.

## 개발

설치된 Xcode와 macOS SDK를 사용하며 외부 패키지 의존성은 없습니다.

```sh
./scripts/build.sh
./scripts/test.sh
open build/Hollow.app
```

`Package.swift`를 Xcode에서 열어 편집할 수 있습니다. 권한 테스트는 `swift run` 대신 Info.plist와 서명이 포함된 `.app`으로 진행하세요. 로컬 ad-hoc 서명은 개발용이며, 바이너리 변경 후 OS가 권한을 다시 요청할 수 있습니다. 배포용 서명·공증·라이선스 처리는 별도 단계입니다.

```text
Sources/Hollow/HollowApp.swift        SwiftUI 메인 화면 / 메뉴바
Sources/Hollow/Model.swift            상태, 프로세스 탐색, 단축키, 설정, 복구
Sources/AudioCore/Engine.mm           Process Tap / 집계 장치 / 실시간 콜백
Sources/AudioCore/DSP.hpp             잔향 / 톤 / 오빗 / 보간 / 피크 상한
Sources/AudioCore/Soundscape.hpp      독립 환경음 / 루프 / DJ / 믹싱
Sources/Hollow/SoundLibrary.swift     소재 디코딩 / 로컬 일본어 음성 생성
Sources/AudioCore/include/AudioCore.h Swift ↔ C ABI
Tests/DSPTests.cpp                   DSP 수치 검증
```

실시간 콜백에서 배열 생성·락·파일 저장·네트워크 접근을 하지 않습니다. DSP 메모리는 시작 전에 준비하고 파라미터는 atomic으로 전달합니다. 오디오는 디스크에 녹음하지 않으며 네트워크로 전송하지 않습니다.

## 이전 0.1 검증 기록 — 2026-09-13

- Xcode 26.2 SDK / Swift 6.2.3 / Apple Silicon에서 release build 성공.
- DSP 테스트: 7 프리셋 × 44.1/48/96kHz, 잔향 꼬리, A/B 정확도, NaN/Infinity 입력, 과대 입력의 출력 상한 통과.
- UndefinedBehaviorSanitizer 테스트 통과.
- AddressSanitizer는 이 환경에서 테스트 코드 진입 전 런타임 초기화의 spin lock에 멈춰 완료하지 못함. 프로세스 샘플로 확인 후 종료했으며 ASan 통과를 주장하지 않음.
- 네이티브 앱 실행과 프리셋 전환, 변경한 설정의 재실행 후 복원 확인.
- 시스템 캡처 실행 중 UI에서 2,188개 누적 버퍼와 0.047054의 0이 아닌 출력 피크 관찰. 실제 소리 경로가 살아 있음을 확인했지만 청감 품질·종단 지연·전체 스트리밍 서비스 호환성 검증을 대체하지 않음.
- 앱별 캡처, JSON 입출력, 타이머, 장치 변경 복구는 코드 구현 상태이며 모든 시나리오의 UI 회귀 테스트는 아직 하지 않음.

## 다음 개발 순서

1. 앱별 캡처·브라우저 자식 프로세스·AirPods/DAC 장치 전환 통합 테스트와 지연 계측.
2. 출력 크기 보정, 제대로 된 리미터, 피치 시프트.
3. 라이선스가 명확한 IR 기반 컨볼루션과 실제 HRTF 구현 및 청감 튜닝.
4. sandbox/서명/공증 검증과 베타 배포.

API 구조는 [Apple의 Core Audio 탭 공식 샘플 설명](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps) 및 설치된 SDK의 `CATapDescription.h`, `AudioHardwareTapping.h`, `AudioHardware.h`를 확인했습니다. 첨부 보고서의 법적 결론과 시장 성공 확률을 이 구현이 입증하는 것은 아닙니다.
